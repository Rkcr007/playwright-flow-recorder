A browser recorder that stays idle while you log in and navigate, captures only the flow you actually want automated — along with what you were verifying and why — then hands it to an AI agent that writes the test in your existing style, reusing the steps and selectors you already have.

Why a recorder that records less

    
Most recorders start capturing at the first click. You get forty events of logging in before the part you cared about.

    

      

        THE SEGMENT MODEL
        
Idle until you say so

        

          Log in, navigate, poke around — none of it is captured. Press ⏺ where the scenario actually starts.
          The login and navigation steps come from your framework, where they already exist and already work.
        

      

      

        INTENT, NOT JUST CLICKS
        
It records what you were checking

        

          ⌥/Alt+Click any element and a menu asks what to verify — has this text, is visible, is enabled,
          this whole row, disappears later. Plus free-text notes in your own words. A click-only recording proves nothing.
        

      

      

        REUSE FIRST
        
Up to 7 selectors per element

        

          Ranked data-testid → id → aria-label → placeholder →
          text → css-path, so the agent can pick a stable one and match it against selectors you already have —
          proposing fixes when yours have drifted.
        

      

    

  


  
  

    
From zero

    
Six commands, and it sits inside your framework

    

      Steps 1–4 are once per repo. Steps 5–6 are how you start each session.
    

    
# 1 · add it to the test repo you already have
npm i -D playwright-flow-recorder

# 2 · wire it to YOUR framework — reads package.json, detects what it can
npx flow-recorder init

# 3 · confirm every path it guessed actually resolves
npx flow-recorder doctor

# 4 · index the steps and selectors you already have
npx flow-recorder index

# 5 · a browser you can log into, that the recorder can attach to
npx flow-recorder chrome

# 6 · attach — and wait, idle, until you press ⏺
npx flow-recorder record


    

      

        WHAT INIT DETECTS
        

          Cucumber, Playwright Test, CodeceptJS or Cypress — from your dependencies. Then your feature directory,
          step directories, primary step file and dry-run command. Anything it can't work out, it prints under
          "review these before recording" rather than guessing silently.
        

      

      

        WHAT IT CREATES
        

          flow-recorder.config.json and the agent's instructions — both committed.
          Recordings, the reuse index and your personal overrides go in .flow-recorder/, added to
          your .gitignore automatically. It never edits your existing test files.
        

      

      

        WHAT YOU NEED
        

          Node 18+, a Chromium-based browser, and an AI coding agent. That's it — no account, no service,
          no telemetry. Firefox and Safari aren't supported.
        

      

    

  


  
  

    
Honest fit

    
Where it earns its keep — and where it won't

    

      

        ✓
        

          
A team with a real step library

          

            When the work isn't "write a test" but "write a test that matches our conventions and doesn't
            duplicate what exists." That reconciliation is the whole value.
          

        

      

      

        ✓
        

          
Manual testers who can demonstrate but not code

          

            userMode: "guided" strips the jargon, picks safe defaults, and explains the finished
            scenario back in plain English so they can check the intent without reading code.
          

        

      

      

        ✕
        

          
A greenfield repo with nothing to reuse

          

            It still works, but every step comes back [NEW] —
            you're mostly getting selector capture. This is the single biggest predictor of disappointment, and
            doctor warns you about it up front.
          

        

      

    


    

      No speed claim. I'm not going to quote you a multiplier I haven't measured. What it removes is
      concrete: hunting selectors in DevTools, re-writing login and navigation, not knowing a step already
      exists, guessing waits, and forgetting what you were verifying. What it doesn't remove: deciding whether
      a value is a fixture or a literal, seeding data so a test can run twice, and the human review
      that @wip exists to demand. Time five scenarios by hand, then five recorded, and count the
      duplicate steps avoided — that's your real number.
    

  


  
  

    
Security, plainly

    
What it touches, and the one thing to actually think about

    

      

        
          
CheckedFinding

        
        
          

            Install-time code
            None. No postinstall, preinstall or prepare script — installing the package executes nothing.
          

          

            Outbound network
            None. The only HTTP call in the codebase is a handshake to 127.0.0.1 to check the browser is up. No telemetry, no analytics.
          

          

            Request bodies
            Never recorded. Network events carry method, path and status only.
          

          

            The debug port
            This is the real one. Chrome's debug protocol is unauthenticated, so any process running as you can drive that browser — cookies and sessions included. It binds to localhost only and uses a dedicated profile, never your everyday one. Don't run it on a shared machine; quit the browser when you're done.
          

          

            Recording contents
            Full page URLs including query strings, visible text, and values you typed. Password-ish fields are masked by pattern — so extend maskPattern for your app's naming, because a sensitive field that doesn't match the pattern comes through in the clear. Recordings are gitignored by default.
          

          

            The onCreate hook
            Runs a shell command when you click ⚡, so a config file committed to a repo could execute something on your machine. Off by default, printed at startup and on every run, and disableable with --no-hooks. Worth a glance in repos you didn't write.
          

          

            Your AI agent
            The recorder is local. Whatever assistant you hand a recording to may not be — that's the step to consider for a sensitive flow, not the recorder.
          

        
      

    

  


  
  

    
Known blind spots

    
Documented, not discovered later

    
    
      
  • Cross-origin iframes aren't captured — payment widgets, embedded SSO. The HUD won't appear inside them.
    • 
      
  • Hover-only menus and drag-and-drop aren't first-class events. Leave a note describing what happened.
    • 
      
  • React <div> data grids with no row semantics can't offer the "check this whole row" assertion. Per-cell asserts, or a shared row key, instead.
    • 
      
  • Chrome 136+ silently ignores the debug port on your default profile — which is why the tool insists on a dedicated one.
    • 
      
  • One session per account on many staging environments: a dry-run will log out your recording browser.
    • 
    

  


  
  

    
What this demo simplifies

    
Three things above aren't in the product

    

      The HUD, its states, the assert predicates, the event shapes and the hand-off panel are the real thing.
      These are not, and you should know before you install it:
    

    

      

        1
        

          
There's no event panel beside your app

          

            Events go to the recorder's terminal and to a .jsonl file. The panel here exists to make
            the stream visible while you click — the real HUD is just the bar.
          

        

      

      

        2
        

          
There's no ⌥ assert button

          

            The real bar has exactly three buttons. You ⌥/Alt+Click an element directly and the palette opens.
            A mode toggle stands in here because Alt+Click is unreliable inside a web page.
          

        

      

      

        3
        

          
Idle clicks leave no trace at all

          

            The greyed "ignored" lines and the counter are invented for this demo, to render an absence. In the
            real recording those clicks simply don't exist — the only thing they can produce is a warning if you
            click for a long time without pressing ⏺, in case you forgot.
